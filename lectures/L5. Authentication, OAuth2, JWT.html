Лекция 5: Аутентификация и JWT в Products API

За два часа добавим вход, профиль пользователя и права администратора. Продолжаем существующий проект с товарами в словаре.

Результат: все читают товары, пользователь смотрит свой профиль, администратор изменяет товары.

Аутентификация и права

ПроверкаВопросПример
АутентификацияКто выполняет запрос?Проверяем пароль или токен.
АвторизацияЧто ему разрешено?Изменять товары может администратор.

401: нет действительного токена или неверный пароль.

403: пользователь известен, но у него нет права на действие.

GET товаров публичный. POST, PUT, PATCH и DELETE требуют роль admin.

Как работает вход

  1. Клиент отправляет логин и пароль на POST /auth/token.
  2. Сервер проверяет пароль по хэшу и возвращает JWT.
  3. Клиент передаёт Authorization: Bearer <token>.
  4. Сервер проверяет токен и находит пользователя.
  5. Для изменения товара сервер дополнительно проверяет роль.

Пароль нужен при входе. Последующие запросы используют токен.

Здесь password flow служит учебным примером FastAPI. Для новых промышленных OAuth2-систем RFC 9700 запрещает этот grant. Обычный вариант OAuth2-входа: Authorization Code с PKCE.

JWT: что нужно знать

header.payload.signature
graph TD A["JWT token"] --> B["Header"] A --> C["Payload"] A --> D["Signature"] B -- "содержит" --> B1["alg: HS256"] B -- "содержит" --> B2["typ: JWT"] C -- "содержит" --> C1["sub: admin"] C -- "содержит" --> C2["exp: 1782048000"] D -- "создаётся из" --> H["Header + '.' + Payload"] D -- "подписывается" --> S["Секретный ключ"] style D fill:#cfc,stroke:#333

sub хранит логин пользователя, exp хранит срок действия. Подпись позволяет проверить, что токен выдал наш сервер.

Содержимое JWT можно прочитать. Пароли и секреты в токен не помещаем. После истечения токена пользователь входит заново.

Схемы пользователя и токена

Новый app/schemas/auth.py

from typing import Literal
from pydantic import BaseModel


class UserRead(BaseModel):
    id: int
    username: str
    role: Literal["user", "admin"] = "user"
    disabled: bool = False


class UserInDB(UserRead):
    hashed_password: str


class Token(BaseModel):
    access_token: str
    token_type: str = "bearer"

Хранилище использует UserInDB. В ответах показываем UserRead, поэтому хэш пароля не попадёт клиенту.

Хэширование пароля

Начало нового app/core/security.py

from pwdlib import PasswordHash

password_hash = PasswordHash.recommended()
DUMMY_HASH = password_hash.hash("not-a-real-password")


def hash_password(password: str) -> str:
    return password_hash.hash(password)


def verify_password(password: str, stored_hash: str) -> bool:
    return password_hash.verify(password, stored_hash)

hash_password() создаёт Argon2-хэш. verify_password() проверяет введённый пароль по сохранённому хэшу.

DUMMY_HASH используем для неизвестного логина, чтобы тоже выполнить проверку пароля.

Проверка логина и пароля

Новый app/services/auth.py

from app.core.security import DUMMY_HASH, verify_password
from app.schemas.auth import UserInDB


def authenticate_user(
    users: dict[str, UserInDB], username: str, password: str,
) -> UserInDB | None:
    user = users.get(username)
    stored_hash = user.hashed_password if user else DUMMY_HASH
    valid = verify_password(password, stored_hash)
    if user is None or not valid:
        return None
    return user

Сервис возвращает пользователя или None. Роутер превратит неудачный вход в одинаковый ответ 401 для неизвестного логина и неверного пароля.

Создание JWT

Продолжение app/core/security.py

from datetime import datetime, timedelta, timezone
import jwt
from app.core.config import Settings


def create_access_token(username: str, settings: Settings) -> str:
    payload = {
        "sub": username,
        "exp": datetime.now(timezone.utc) + timedelta(
            minutes=settings.access_token_expire_minutes,
        ),
    }
    return jwt.encode(
        payload, settings.jwt_secret_key.get_secret_value(),
        algorithm="HS256",
    )

Токен хранит логин и срок действия. Алгоритм HS256 фиксируем в коде, ключ и срок берём из настроек.

Проверка JWT

Продолжение app/core/security.py

def decode_access_token(token: str, settings: Settings) -> str:
    payload = jwt.decode(
        token, settings.jwt_secret_key.get_secret_value(),
        algorithms=["HS256"],
        options={"require": ["sub", "exp"]},
    )
    return payload["sub"]

PyJWT проверяет подпись и срок. require требует оба поля. Функция возвращает логин, чтобы найти пользователя.

Роль читаем из хранилища при каждом запросе. В JWT её не записываем.

Bearer token и ошибка 401

Начало нового app/dependencies/auth.py

from typing import Annotated
from fastapi import Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer
from jwt.exceptions import InvalidTokenError
from app.core.config import SettingsDep
from app.core.security import decode_access_token
from app.db.fake_users import UsersDep
from app.schemas.auth import UserRead

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="auth/token")
TokenDep = Annotated[str, Depends(oauth2_scheme)]


def invalid_credentials() -> HTTPException:
    return HTTPException(
        status_code=401, detail="Неверные учётные данные",
        headers={"WWW-Authenticate": "Bearer"},
    )

OAuth2PasswordBearer извлекает токен из заголовка и добавляет Authorize в Swagger UI. tokenUrl указывает на наш endpoint входа.

Текущий пользователь

Продолжение app/dependencies/auth.py

def get_current_user(
    token: TokenDep, users: UsersDep, settings: SettingsDep,
) -> UserRead:
    try:
        username = decode_access_token(token, settings)
    except (InvalidTokenError, ValueError, TypeError):
        raise invalid_credentials() from None
    user = users.get(username)
    if user is None:
        raise invalid_credentials()
    if user.disabled:
        raise HTTPException(status_code=403, detail="Пользователь заблокирован")
    return UserRead(**user.model_dump())


CurrentUserDep = Annotated[UserRead, Depends(get_current_user)]

Одна зависимость проверяет токен, существование пользователя и блокировку. Возвращает публичную модель без хэша.

Права администратора

Завершение app/dependencies/auth.py

def require_admin(user: CurrentUserDep) -> UserRead:
    if user.role != "admin":
        raise HTTPException(status_code=403, detail="Недостаточно прав")
    return user


AdminUserDep = Annotated[UserRead, Depends(require_admin)]

Сначала выполняется get_current_user, затем проверка роли. Обычный пользователь получает 403.

Для защиты операции достаточно добавить параметр _admin: AdminUserDep.

Auth-роутер

Начало нового app/routers/auth.py

Форма принимает поля username и password. Вход отправляем как form data, а не JSON.

Endpoint входа

Продолжение app/routers/auth.py

@router.post("/token", response_model=Token)
def login(form: LoginForm, users: UsersDep, settings: SettingsDep) -> Token:
    user = authenticate_user(users, form.username, form.password)
    if user is None:
        raise invalid_credentials()
    if user.disabled:
        raise HTTPException(status_code=403, detail="Пользователь заблокирован")
    return Token(access_token=create_access_token(user.username, settings))

Используем def, чтобы вычисление хэша выполнялось в пуле потоков. При успехе клиент получает access_token и token_type="bearer".

Готовые решения для аутентификации

РешениеЧто предоставляетКогда подходит
FastAPI UsersБиблиотека с готовыми роутами регистрации, входа, сброса пароля и проверки email.Управление пользователями внутри FastAPI-приложения.
KeycloakОтдельный сервер: общий вход в несколько приложений, роли и управление пользователями.Нужен единый вход и собственное развёртывание системы аутентификации.
Auth0Облачный сервис с готовой страницей входа, социальным входом и двухфакторной проверкой.Удобнее использовать внешний сервис аутентификации.

Библиотеку подключаем к своему API. Keycloak и Auth0 берут вход на себя, а наше API проверяет токены выбранного провайдера и права на операции.

FastAPI Users находится в режиме сопровождения: обновления безопасности и зависимостей продолжаются, новые функции не добавляются. Учитываем это при выборе для нового проекта.

Результат занятия

  • Есть два пользователя, вход и профиль.
  • Пароли проверяем по хэшам, JWT проверяем по подписи и сроку.
  • Зависимости дают 401 для неверных учётных данных и 403 при недостаточных правах.
  • Администратор выполняет CRUD, чтение доступно всем.

На этом обязательная практика закончена. Автоматические тесты разберём на следующем занятии.

Учебные словари сбрасываются при перезапуске. Вне локального занятия нужны HTTPS и другие пароли. Refresh token и отзыв токенов требуют отдельной реализации.
