Лекция 6: Тесты с pytest

Добавим автоматические проверки в наш Products API. Проверим товары, вход и права пользователя.

Тесты будем запускать без отдельного сервера через TestClient.

Наш проект

app/
├── main.py                # create_app(), /health
├── core/                  # config.py, lifespan.py, security.py
├── db/                    # fake_db.py, fake_users.py
├── dependencies/          # db.py, settings.py, auth.py
├── routers/               # product.py, auth.py
├── schemas/               # product.py, auth.py
└── services/              # product.py, auth.py

Товары и пользователи хранятся в словарях. При старте lifespan создаёт отдельные копии в app.state.

В текущем коде чтение /products тоже требует токен. Изменять товары может только admin. Вход: /auth/token, профиль: /auth/me.

pytest

uv add --dev pytest

pytest находит функции test_* в файлах test_*.py и выполняет их. HTTP-клиент уже установлен вместе с fastapi[standard].

Создаём каталог tests/. В pyproject.toml добавляем:

[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["."]

Тесты запускаем из корня проекта командой uv run pytest. pythonpath позволяет импортировать пакет app.

Тестовые настройки

Начало нового tests/conftest.py

import os

os.environ.update(
    DEBUG="false",
    SECRET_KEY="test-" + "x" * 64,
    ADMIN_PASSWORD="admin-pass",
    USER_PASSWORD="user-pass",
)

Задаём отдельные учебные значения до импорта app.main: fake_users.py читает настройки и хэширует пароли при импорте.

Переменные окружения имеют приоритет над .env. Файл .env менять не нужно. Ключ соответствует ограничению min_length=64.

Фикстура клиента

Продолжение tests/conftest.py, после тестовых настроек

import pytest
from fastapi.testclient import TestClient
from app.main import create_app


@pytest.fixture
def client():
    with TestClient(create_app()) as test_client:
        yield test_client

Фикстура готовит объект для теста. Pytest сам подставляет её по имени аргумента client. Импортировать conftest.py в тестах не нужно.

Для каждого теста создаётся новый клиент. Вход в with запускает lifespan, выход завершает его. yield передаёт клиент тесту.

Первый тест

Новый tests/test_health.py

def test_health(client):
    response = client.get("/health")

    assert response.status_code == 200
    assert response.json() == {
        "status": "ok",
        "products_count": 5,
    }

В fake_db пять товаров. Проверяем статус и JSON ответа. Если условие в assert ложно, pytest покажет различие.

TestClient вызывает приложение внутри процесса. Даже для наших async def эндпоинтов тест пишем обычной функцией def.

Вход

Новый tests/test_auth.py

def test_login(client):
    response = client.post(
        "/auth/token",
        data={"username": "admin", "password": "admin-pass"},
    )

    assert response.status_code == 200
    body = response.json()
    assert body["token_type"] == "bearer"
    assert body["access_token"]

Вход принимает форму, поэтому используем data=. Для JSON-тела товара будем использовать json=.

Токен для тестов

Продолжение tests/conftest.py

@pytest.fixture
def admin_headers(client):
    response = client.post(
        "/auth/token",
        data={"username": "admin", "password": "admin-pass"},
    )
    assert response.status_code == 200
    token = response.json()["access_token"]
    return {"Authorization": f"Bearer {token}"}

Фикстура может зависеть от другой фикстуры. admin_headers выполняет вход через тот же client, который получает тест.

В примерах используем настоящую выдачу и проверку JWT.

Список товаров

Новый tests/test_products.py

def test_list_products(client, admin_headers):
    response = client.get("/products", headers=admin_headers)

    assert response.status_code == 200
    assert [p["id"] for p in response.json()] == [1, 3, 5]

    response = client.get(
        "/products",
        params={"only_available": False},
        headers=admin_headers,
    )
    assert response.status_code == 200
    assert len(response.json()) == 5

По умолчанию only_available=True, поэтому API возвращает три доступных товара. Через params передаём query-параметры.

Создание товара

Продолжение tests/test_products.py

def test_create_product(client, admin_headers):
    response = client.post(
        "/products",
        json={"name": "Gaming Mouse", "category": "electronics", "price": 49.9},
        headers=admin_headers,
    )

    assert response.status_code == 201
    body = response.json()
    assert body["id"] == 6
    assert body["name"] == "Gaming Mouse"
    assert body["price"] == 49.9

    saved = client.get(f"/products/{body['id']}", headers=admin_headers)
    assert saved.status_code == 200
    assert saved.json() == body

Проверяем и ответ POST, и сохранение товара через GET. ID равен 6, потому что в свежем словаре уже есть товары с ID от 1 до 5.

Обновление товара

Продолжение tests/test_products.py

def test_update_product(client, admin_headers):
    response = client.patch(
        "/products/1",
        json={"price": 99.9},
        headers=admin_headers,
    )

    assert response.status_code == 200
    assert response.json()["price"] == 99.9
    assert response.json()["name"] == "Product 1"

    saved = client.get("/products/1", headers=admin_headers)
    assert saved.status_code == 200
    assert saved.json()["price"] == 99.9

PATCH меняет переданное поле и сохраняет прежнее название. Тест использует свою копию начальных данных.

Удаление товара

Продолжение tests/test_products.py

def test_delete_product(client, admin_headers):
    response = client.delete("/products/1", headers=admin_headers)

    assert response.status_code == 204
    assert response.content == b""

    response = client.get("/products/1", headers=admin_headers)
    assert response.status_code == 404
    assert response.json() == {"detail": "Product not found"}

У ответа 204 нет тела. Повторное чтение проверяет удаление и наш обработчик ProductNotFoundError.

Валидация

В начало tests/test_products.py добавляем импорт, затем дописываем тест

import pytest

@pytest.mark.parametrize("price", [0, -1])
def test_invalid_price(client, admin_headers, price):
    response = client.post(
        "/products",
        json={"name": "Gaming Mouse", "category": "electronics", "price": price},
        headers=admin_headers,
    )

    assert response.status_code == 422
    errors = response.json()["detail"]
    assert any(error["loc"] == ["body", "price"] for error in errors)

parametrize запускает один тест два раза. Проверяем поле с ошибкой: цена должна быть больше нуля.

Нет токена

В начало tests/test_auth.py добавляем импорт, затем дописываем тест

import pytest

@pytest.mark.parametrize("path", ["/auth/me", "/products", "/products/1"])
def test_token_required(client, path):
    response = client.get(path)

    assert response.status_code == 401
    assert response.headers["WWW-Authenticate"] == "Bearer"

Три защищённых маршрута возвращают 401 без заголовка авторизации.

Неверный пароль

Продолжение tests/test_auth.py

@pytest.mark.parametrize("username", ["admin", "unknown"])
def test_invalid_login(client, username):
    response = client.post(
        "/auth/token",
        data={"username": username, "password": "wrong-password"},
    )

    assert response.status_code == 401
    assert response.json() == {"detail": "Неверные учётные данные"}
    assert response.headers["WWW-Authenticate"] == "Bearer"

Неверный пароль и неизвестный логин дают одинаковую ошибку.

Права пользователя

Продолжение tests/test_auth.py

def test_user_cannot_create_product(client):
    login = client.post(
        "/auth/token",
        data={"username": "user", "password": "user-pass"},
    )
    assert login.status_code == 200
    headers = {"Authorization": f"Bearer {login.json()['access_token']}"}

    profile = client.get("/auth/me", headers=headers)
    assert profile.status_code == 200
    assert profile.json()["role"] == "user"
    assert "hashed_password" not in profile.json()

    response = client.post(
        "/products",
        json={"name": "Gaming Mouse", "category": "electronics", "price": 49.9},
        headers=headers,
    )
    assert response.status_code == 403

Пользователь успешно входит и получает профиль, но создание товара требует роль admin.

Запуск

uv run pytest -v
uv run pytest tests/test_products.py
uv run pytest tests/test_auth.py::test_login

Первая команда запускает весь набор, вторая один файл, третья один тест.

tests/
├── conftest.py
├── test_health.py
├── test_products.py
└── test_auth.py

Каждый тест должен проходить отдельно. Если результат зависит от порядка, проверяем, не используются ли общие изменяемые данные.

Практика

Сначала собираем примеры и запускаем весь набор. Затем добавляем несколько проверок самостоятельно:

  1. PUT заменяет товар и возвращает новые значения.
  2. Фильтр category=category1 возвращает товары с ID 1 и 5.
  3. Повреждённый Bearer-токен даёт 401 на /auth/me.
  4. Обычный пользователь читает товары, но не может удалить товар.

Для каждого теста выбираем понятное имя и проверяем ожидаемый статус и результат.

Итоги

  • pytest запускает тесты и проверяет assert.
  • TestClient отправляет запросы приложению без Uvicorn.
  • Фикстуры дают каждому тесту клиент и свежие данные.
  • Тесты проверяют товары, валидацию, вход и права.

Дальше подключим базу данных. Эти проверки помогут сохранить поведение API при замене словаря.
