Лекция 4: Структура FastAPI

В Products API уже есть CRUD и Pydantic-схемы. Теперь разложим код по модулям и покажем Depends на получении хранилища.

Стартовая точка

В нашем проекте уже созданы main.py, schemas.py, service.py и db.py. Добавим роутер и зависимости.

Задача — сделать код понятнее, сохранив прежние методы, параметры и пути /products.

Слои приложения

Запрос → роутер → сервис → хранилище
ЧастьЧто делает
РоутерПринимает HTTP-параметры и вызывает сервис
СервисВыполняет операции с товарами и проверяет правила
ХранилищеСодержит данные; пока это словарь
СхемыОписывают и проверяют данные запроса и ответа

Например, проверка итогового товара после PATCH относится к сервису, а путь и статус ответа — к HTTP-слою.

Структура проекта

app/

main.py собирает приложение. dependencies.py выдаёт нужные объекты эндпоинтам. Для пакетов создаём пустые __init__.py и используем импорты от app.

APIRouter

Роутер объединяет эндпоинты одного ресурса. Общий префикс и теги задаём один раз.

app/routers/products.py

from fastapi import APIRouter

router = APIRouter(prefix="/products", tags=["Products"])
БылоСтанет
@app.get("/products")@router.get("")
@app.get("/products/{product_id}")@router.get("/{product_id}")

Префикс /products и путь операции складываются. Пустой путь "" сохраняет URL без завершающего слеша.

Сервис товаров

В app/service.py уже находятся операции с товарами. Сохраняем существующий ProductService со статическими методами.

from app.service import ProductService

product = ProductService.get_product_by_id(1)

Роутер вызывает сервис. Сервис выполняет действие и обращается к хранилищу. Для разделения этих обязанностей не нужно менять сервис на экземпляр класса.

Depends

Depends сообщает FastAPI, откуда взять объект для параметра эндпоинта.

app/dependencies.py

from typing import Annotated

from fastapi import Depends

from app.db import fake_db

def get_db() -> dict:
    return fake_db


DbDep = Annotated[dict, Depends(get_db)]

Передаём функцию get_db без скобок. FastAPI сам вызовет её перед выполнением эндпоинта. Пока вместо настоящей БД получаем наш словарь.

Роутер товаров

Переносим эндпоинты, сохраняя прежние вызовы сервиса. Покажем GET и POST; остальные операции переносятся так же.

app/routers/products.py

from typing import Annotated

from fastapi import APIRouter, Path

from app.schemas import ProductCreate, ProductRead
from app.service import ProductService

router = APIRouter(prefix="/products", tags=["Products"])
ProductId = Annotated[int, Path(ge=1)]


@router.get("/{product_id}", response_model=ProductRead)
def get_product(product_id: ProductId):
    return ProductService.get_product_by_id(product_id)


@router.post("", response_model=ProductRead, status_code=201)
def create_product(data: ProductCreate):
    return ProductService.create(data)

Роутер описывает HTTP-контракт, сервис выполняет действие. Для работы со словарём достаточно обычных def.

Сборка приложения

Подключим роутер к FastAPI.

app/main.py

from fastapi import FastAPI

from app.routers import products

app = FastAPI(title="Products API")
app.include_router(products.router)

Запуск из корня проекта:

uv run fastapi dev app/main.py

Пути сохраняются: /products и /products/{product_id}. Префикс версии API пока не добавляем.

Ошибки сервиса

Сервис сообщает, что товар не найден. Приложение превращает эту ошибку в HTTP 404.

Добавляем в app/main.py

from fastapi import Request
from fastapi.responses import JSONResponse

from app.service import ProductNotFoundError


@app.exception_handler(ProductNotFoundError)
async def product_not_found(request: Request, error: ProductNotFoundError):
    return JSONResponse(status_code=404, content={"detail": "Product not found"})

Обработчик принимает запрос и исключение и возвращает ответ. HTTPException внутри сервиса не нужен.

FastAPI сам возвращает 422 для невалидных входных параметров. Ошибку ручной проверки результата PATCH нужно обработать отдельно: сервис поднимает свою ошибку, а HTTP-слой возвращает 422. Сохраняем товар только после успешной проверки.

Зависимость в эндпоинте

Для демонстрации добавим учебный эндпоинт: он получает хранилище и показывает число записей.

Добавляем в app/main.py

from app.dependencies import DbDep


@app.get("/health")
def health(db: DbDep):
    return {"status": "ok", "products_count": len(db)}

Параметр db получен из get_db(). По умолчанию результат зависимости переиспользуется внутри одного запроса.

Getter возвращает существующий словарь. Новый пустой словарь на каждый запрос создавать не нужно.

Lifespan

Некоторые ресурсы создают при старте приложения. Для этого используют lifespan: код до yield выполняется при запуске, после него — при завершении.

Пример: сохраняем ссылку на хранилище

from contextlib import asynccontextmanager

from fastapi import FastAPI

from app.db import fake_db


@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.db = fake_db
    yield

При сборке заменяем создание приложения на app = FastAPI(lifespan=lifespan). Затем подключаем роутер и обработчики, как раньше.

В dependencies.py заменяем getter:

from fastapi import Request


def get_db(request: Request) -> dict:
    return request.app.state.db

Новый getter объявляем перед DbDep. Для словаря lifespan необязателен; позже здесь будем открывать и закрывать ресурсы настоящей БД.

Настройки

Значения, которые отличаются между окружениями, удобно вынести в настройки.

uv add pydantic-settings

app/core/config.py

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    app_name: str = "Products API"
    debug: bool = False

    model_config = SettingsConfigDict(
        env_file=".env", env_file_encoding="utf-8",
    )

Создайте app/core/__init__.py. В main.py замените создание приложения, прочитав настройки один раз:

from app.core.config import Settings

settings = Settings()
app = FastAPI(title=settings.app_name, debug=settings.debug, lifespan=lifespan)

.env

Локальные значения храним в файле .env в корне проекта:

APP_NAME=Products API Local
DEBUG=false

pydantic-settings прочитает значения и преобразует их по типам. Переменные окружения имеют приоритет над файлом.

Добавьте .env в .gitignore. В репозиторий можно положить .env.example с примером настроек без секретов.

Практика

  1. Перенесите CRUD в routers/products.py и подключите роутер.
  2. Сохраните прежние вызовы ProductService из эндпоинтов.
  3. Добавьте get_db(), DbDep и учебный эндпоинт /health.
  4. Добавьте обработчик ProductNotFoundError и проверьте ответ 404.
  5. Проверьте весь CRUD в Swagger UI: прежние пути и фильтры, невалидные данные, PATCH и удаление.

Дополнительно: получайте хранилище из app.state через lifespan и вынесите название приложения и debug в настройки.

Итоги

  • APIRouter группирует эндпоинты, сервис выполняет операции.
  • Depends передаёт хранилище в учебный эндпоинт.
  • main.py собирает приложение и связывает его части.

На следующей лекции используем зависимости для получения текущего пользователя и проверки доступа.
